So there are TWO distinct differences, and neither is plumbing:

 1. **The reduction SPLITS on whether the queried PQ ciphertext is the challenge
    one** (`ct_PQ = corr.`3`) and the game does not. Closing this needs the split
    introduced on the game side -- `case (ct_PQ = ...)` -- with the challenge
    branch discharged from the correctness invariant the coupling already carries
    (`corr.`5 = ev_decaps corr.`2 corr.`3`), which is exactly what makes the
    reduction's two branches agree with the game's single one.
 2. **The game reads the packed T scalar `dk.`2` where the reduction re-derives it
    from its seed** via `NG.randomscalar(seed_T)`, and it also calls
    `NG.generator` the game does not.

THE BOTH-SIDED-EXTRAS EXTENSION (designed c257, not yet built)
=============================================================
`hop_15_initialize` on the `_expanded` cells needs extras on BOTH sides, which
`_extra_det_target` currently refuses. Measured shapes (flat bodies, events only):

  LEFT  = reduction `R_Correct_Ideal`, 12 events:
      keygen, encaps, DECAPS, S(nseed), rs, gen, exp, S(nseed), rs, gen, exp,
      S(kdf_nout)
  RIGHT = game `KEM_INDCCA_Random`, 18 events:
      keygen, S(nseed), rs, gen, exp, encaps, S(nseed), rs, gen, exp, EXP, ETS,
      ESS, ENC, ENC, GET, EVAL, S(kdf_nout)

So the delegate side has ONE live-det extra (`decaps`) and the game side has SEVEN
extras -- its whole KDF chain -- every one of them DEAD, because the game samples
`ssStar <$ dbs_kdf_nout` fresh and discards the encapsulated `ss` (`ss_unused`).

The build, and it reuses machinery that already exists:
 - `_live_out` is COMPONENT-precise (a live `t.`2` revives only the 2nd component
   of `t`'s defining tuple literal), so `_drop_result_dead` correctly reports the
   whole KDF chain dead even though its results pass through `_tup_0 <- (ss, ct)`
   whose OTHER component is live. Do not write a fresh liveness pass.
 - Delegate-side extra -> `call{2} (M_m_det ...)` as now (result LIVE, and the
   drop is what states the coupling's `ev_` fact).
 - Game-side extra -> `exists* (glob M){1}; elim* => g. call{1} (M_m_pres g).`,
   gated on `_drop_result_dead`, and the `(M, m)` pair RETURNED in the route's
   third tuple element (it is already a `pres_methods` slot -- the route just
   returns `set()` today).
 - `_extra_det_target` becomes: match positionally into `common`; the delegate's
   alignment target is `common` in the GAME's order with delegate extras
   re-inserted (unchanged); the WALK is driven by an ordered op list built from
   the game's own event order -- `dropL` for a dead game extra, `match`, then any
   delegate extras attached after that common event as `dropR`.

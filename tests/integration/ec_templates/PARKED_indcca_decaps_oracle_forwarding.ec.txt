WHY THIS IS PARKED RATHER THAN LANDED
=====================================
It needs TWO coordinated changes, and the second has a blast radius that must be
MEASURED, not predicted: the hop coupling is shared by every hop in the chain and
by the byequiv bridges, so widening it is not a two-lemma change.

  1. WIDEN THE COUPLING with the challenger's decapsulation key.
  2. ADD A ROUTE for the forwarding `decaps` shape (script B below).

THE DEFECT: THE ESTABLISHING SIDE ESTABLISHES TOO LITTLE
========================================================
`hop_3_decaps` relates the game (which decapsulates LOCALLY with its own packed
key) to the reduction (which FORWARDS to the IND-CCA challenger's `decaps`
oracle):

    left :  dec_ss_PQ     <@ KEM_PQ.decaps(GameCaseSplitReal.pq_keys.`2, ct_PQ)
    right:  dec_ss_PQ_opt <@ KEM_PQ_c.KEM_INDCCA_Real(KEM_PQ).decaps(ct_PQ)

For these to agree, the game's packed decapsulation key must equal the
challenger's. The emitted coupling carries

    GameCaseSplitReal.pq_keys.`1 = RB.ek_PQ        (the ENCAPSULATION key)

and says nothing about `.`2`. So `hop_3_initialize` -- which is CLOSED, at
`synth-param` -- establishes a coupling too weak for its own `decaps` to consume.
This is the ORDERING RULE failing in a way a green cell does not reveal: the
establishing side compiles, and only the consumer notices what is missing.

The needed conjunct is

    GameCaseSplitReal.pq_keys.`2{1} = KEM_PQ_c.KEM_INDCCA_Real.dk{2}

and it is SOUND, not merely convenient: both sides come from the same
`KEM_PQ.keygen()`. MEASURED -- with the conjunct added to the post by hand,
`hop_3_initialize` still closes **with its existing tactic completely
unchanged**, i.e. the widening costs no new tactic work on the establishing
side. (A coupling can also be TOO STRONG -- see the parked `hop_7_initialize`,
which is exactly that case -- so this check is the point, not a formality.)

WHAT THE ROUTE MUST DO, AND THE THREE TRAPS
===========================================
Structurally it is `_shape_peel` again -- `inline *`, if-tree walk, `seq n n :
(#pre /\ ={live})` for a branch-free run before a branch -- plus ONE new
element: the forwarding branch's right-hand side carries TWO DEAD GUARDS that
`inline *` exposes, and both must be eliminated before the two sides align.

  * `if (ct0 = KEM_PQ_c.KEM_INDCCA_Real.ctStar)` -- the inlined challenger's own
    "refuse to decapsulate the challenge" test. FALSE here, and the premise is a
    THREE-STEP CHAIN through the coupling: the enclosing branch gives
    `ct_PQ{1} <> GameCaseSplitReal.kem_ct{1}`, then
    `GameCaseSplitReal.kem_ct{1} = RB.kem_ct{2}`, then
    `RB.kem_ct{2} = KEM_PQ_c.KEM_INDCCA_Real.ctStar{2}`. Needs
    `move=> &m; auto => /#`; a bare `auto` does not close it.
  * `if (false)` -- a literal, left by the canonicalizer where the reduction
    handles the oracle's `None`. Closes with `first by move=> &m; auto`.

TRAP 1 -- `wp; sim` DOES NOT WORK HERE, unlike the sibling
`_synth_sim_field_rename` route. This coupling contains PROJECTIONS
(`pq_keys.`1`, `pq_keys.`2`, `ctStar.`1`), and `Mpv2` can only represent
variable-to-variable pairs, so `sim` fails with "cannot infer the set of
equalities". Every leaf here must use the smt-based `_straight_peel` shape.
A route selecting its leaf finisher should therefore gate on whether the
coupling text contains a `.`k` projection -- NOT on the proof or game name.

TRAP 2 -- `rcondf{2} <n>` POSITIONS SHIFT. Eliminating the first `if` at
position 2 renumbers the second from 4 to 5 (the branch body is spliced in
where the `if` stood). SOLVED in c251: use EC's code-position PATTERN instead
of a number -- `rcondf{2} ^if` means "the first `if` on side 2", so the
positions never have to be computed at all. Validated: the whole script above
with both numbers replaced by `^if` compiles EXIT 0
(`.ec-tmp/c251_pat.ec`). Prefer the pattern form in any emitted route.

TRAP 3 -- `do ! (wp; call (_: true))` is length-independent and preferable to
emitting N copies, but it still needs the TRAILING `wp; skip => /#`: an
assignment ABOVE the first call is left standing otherwise, and `skip` then
fails with "left instruction list is not empty" (the same trap
`_straight_peel` already documents).

STATUS AFTER c251: THE COUPLING HALF IS BUILT; THE ROUTE IS BLOCKED ON A
FLAT-STATE FIDELITY GAP
=======================================================================
The coupling half (step 1) is written, gated, and measured -- it lives in
`stash@{0}` as `_forwarded_chal_key_coupling`, a separately-gated builder
appended in `_live_state_coupling` beside `wchal`/`spc`/`wdk`. It adds the
conjunct to `hop_3`/`hop_12` (`initialize`, `decaps`, `pr`) and
`CG_expanded_INDCCA_PQ` still ec_compiles EXIT 0 at 9 admits, so the widening
breaks none of the currently-closed hops. It is stashed rather than committed
because on its own it closes ZERO admits.

WHAT ACTUALLY BLOCKS STEP 2, and it is not the tactic: **the FLAT STATES DO NOT
FAITHFULLY MODEL THIS SHAPE'S CONTROL FLOW.** Measured structurally (not from a
text prefix -- see the lesson below):

    flat right body, inner ELSE          real module after `inline *`
    ------------------------------       ----------------------------
    Assign                               ct0 <- ct_PQ
    If[ct_PQ = challenger_ctStar]        if (ct0 = ...ctStar) { .. } else { .. }
    If[! _r15]                           dec_ss_PQ_opt <- _r00
      If[false]                          if (false) { .. } else { .. }

THREE `if`s in the flat body, TWO in the module the lemma actually relates. So a
route that counts dead guards off the flat state emits the wrong number of
`rcondf`s. This is the same class as the `seq`-index hazard
`_synth_sim_field_rename` gates against with `_delegate_flat_names`, but worse:
there the flat state FOLDED a delegate call (one statement fewer), here it
carries an extra BRANCH the real module does not have.

Two ways forward, neither attempted:
  (a) emit `do ! (rcondf{2} ^if; first by move=> &m; auto => /#).` and let EC
      decide how many dead guards there are -- the pattern form makes this
      expressible, and a guard that is not provably false stops the loop
      cleanly. Needs care about what the peel then faces if a LIVE `if` remains.
  (b) derive the route from the REAL rendered modules rather than the flat
      states. `module_translator` already renders them for the lemma; the peel
      routes just happen to read `_flat_state_module` instead. This is the
      principled fix and is an architectural change, not a tactic tweak.

A THIRD MISREAD TO AVOID (cost c251 a wasted change): the flat bodies share a
long identical PREFIX, so a body dump truncated to a fixed width shows them as
identical and invites the conclusion "these differ only by the leading
`<ret> <- witness` seed". They do not. Dump a STRUCTURAL skeleton (statement
kinds per branch) or print the computed predicate, never a text prefix.
